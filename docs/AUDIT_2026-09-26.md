Scope: `main` at `6389f92`, which includes Part 1, Part 2 and Yaseer's Part 3 (CLI, REST API, web UI,
GeoTIFF export, HTML report, visualisations, failure log). Every row of `FEATURES.csv` (86 features) was

## 0. Read this first

### 0.1 What the project is

`chandralign` registers a Chandrayaan-2 image (**source**: OHRC 0.25–0.3 m, TMC-2 ~5 m, IIRS ~80 m
hyperspectral) against a lunar **reference** (LRO NAC ~0.5–1.3 m, LRO WAC ~100 m, SELENE TC ~10 m map
tiles, SELENE MI ~15–20 m map tiles). "Register" means: find corresponding points between the two images
and a geometric model that maps one onto the other. The problem statement (SIH26166) asks for:
- **sub-pixel accuracy**,
- match points **uniformly distributed** over the image,
- the metrics **RMSE, inlier count, inlier ratio** (plus spatial coverage),
- robustness to **illumination, viewpoint and scale** differences.

The team's own rule is that the tool must **refuse honestly** (tier `REJECTED`, with failure modes) rather
than return a confident wrong answer.

### 0.2 Layout you need

| Path | What it is |
|---|---|
| `src/chandralign/pipeline.py` | `register_bundle()` / `register()`: one registration end to end (match → fine stage → gates → tier). The Part 2 → Part 3 handoff. |
| `src/chandralign/matching/` | matcher adapter (vismatch models), routing (`routing.py`, `regime.py`), cascade, RIFT2, rotation, MI similarity, licence gate |
| `src/chandralign/estimate/` | robust estimation (MAGSAC/RANSAC), models (affine/homography/TPS), geometry filter, scale checks |
| `src/chandralign/refine/` | `subpixel.py` (per-point refinement), `uniformity.py` (grid thinning, Delaunay gap) |
| `src/chandralign/evaluate/` | control gates, quality tiers, failure log, metrics |
| `src/chandralign/geometry/` | projection / ground models, footprints, sun geometry, geoprior |
| `src/chandralign/product/` | Part 3 exports: `warp.py` (GeoTIFF), `matchpoints.py` (CSV/GeoJSON), `provenance.py`, `report.py` |
| `src/chandralign/cli.py`, `api.py`, `ui/` | Part 3 entry points: CLI, FastAPI backend, browser UI (`ui/app.js`) |
| `scripts/register_*.py` | **The validated research path.** Every real-data result in `reports/` comes from these scripts, not from the CLI/API. |
| `configs/default.yaml`, `configs/regimes.yaml` | thresholds, tiers, stage switches, `default_matcher: eloftr` |
| `reports/*.json`, `docs/*_protocol.md`, `docs/*_results.md` | committed evidence and frozen protocols |

### 0.3 How to run things

```bash
cd chandrayana2
export PYTHONPATH=src MPLBACKEND=Agg
.venv/Scripts/python -m pytest -q                 # quick suite (~724 tests, ~0 failures today)
.venv/Scripts/python -m pytest -q -m ""           # full suite incl. slow real-data tests
.venv/Scripts/python scripts/sabotage.py --target all   # 70 mutations; all must be "caught"
```
- Real data (16 GB) lives at `C:/chandralign-data/raw`; `data/raw` is a symlink to it.
- There is a CUDA GPU with **6 GB**, and the machine has 15 GB RAM. Two heavy GPU jobs at once will
  thrash, so don't run them together.

### 0.4 Ground rules (learned the hard way during this audit)

1. **Never run `scripts/sabotage.py` on a working tree that anything else is using.** It mutates `src/`
   files one at a time and restores them afterwards. During this audit it silently changed 3 of 15 TMC-2 → TC
   results for a concurrent run. Run it in a `git worktree`, or when nothing else is running.
2. **Run heavy real-data measurements from a clean snapshot:**
   `git archive HEAD | tar -x -C <scratch>/clean`, then `PYTHONPATH=<scratch>/clean/src`.
3. **Frozen-protocol discipline (the project's own rule):** write the acceptance criterion and commit it
   *before* you measure. Take thresholds from outside the experiment's own data. Do not amend a rule after
   seeing results without recording the amendment and re-scoring on fresh windows.
4. **Report accuracy in SOURCE pixels, as p50 and p95.** The median alone hides the tail, and the tail is
   where the product visibly tears. Always say which pixel (source or reference) and which point set.
5. **Two agents may work in parallel.** Use separate branches or worktrees. The one file both tracks touch
   is `pipeline.py` (see §2 for how to split the work).

### 0.5 Units and words used below

- **src px / ref px:** a pixel of the source (CH-2) image / of the reference image. For TMC-2 → TC,
  1 TC px ≈ 2 TMC-2 px (the scripts resample into a "fine frame" of ~1.47–1.51 TMC-2 px per fine px).
- **Script path:** `scripts/register_*.py`. **Product path:** `cli.py` / `api.py` → `register_bundle`.
- **Self-consistency evidence:** checks that reuse the same images or the same matcher (known-shift gate,
  multi-matcher agreement, TPS "held-out" points drawn from the affine's own inliers). Useful, but not
  ground truth.
- **Independent evidence:** matcher-free NCC probes, the mutual-information (MI) peak, and cross-reference
  agreement. Even these see the same two images, so they can share a shading bias with the matcher.

### 1.3 The one-paragraph diagnosis

The algorithms are real and they reproduce. But **all the matcher intelligence lives in `scripts/`, and the
shipped tool (CLI, API, UI) runs none of it.** The product also has a **sub-pixel refinement bug that makes
points worse**. It **reports an RMSE for a geometry it does not deliver**, and **the one gate built to catch
confident wrong answers is never called**. The web UI shows **fabricated numbers**. On accuracy, only
TMC-2 → TC and IIRS → WAC have independent sub-pixel evidence, and only at the median. OHRC → NAC is
**not sub-pixel in OHRC pixels** by any independent measure. Several measured upgrades (§6) could close much
of the gap.

## 3. Critical issues

### C-01 [A] The CLI and API cannot register real data; they never reach the validated path

**Where:**
- `cli.py:76-83` and `api.py:234-244` call
  `register_bundle(next(iter_tiles(src)), next(iter_tiles(ref)), matcher="sift")`.
- `pipeline.py:372,381` (`matcher="sift"` defaults).
- The same `"sift"` default appears in `control_gates.py:295`, `cascade.py:373`, `cli.py:23` and
  `api.py:198,335`.

**What is wrong:** the CLI and API register the **first 1024-px tile of the source against the first
1024-px tile of the reference**, which are the top-left corners of two products and usually unrelated
ground. They default to **SIFT**, which the project's own evidence measured as the floor: 44% core success
and 0/10 on cross-modal (`reports/default_matcher_selection.json`). `configs/regimes.yaml` says
`default_matcher: eloftr`. The product path never calls `routing.choose`, so none of the following ever
runs: routing, the minima-loftr fallback, xoftr for cross-modal pairs, the scale-bridging cascade, the MIND
coarse lock, the geoprior, the rotation prior, the MI check, the DEM terrain filter, parallax and the scale
check.

**Evidence:**
- **TMC-2 → TC (the headline pairing):**
  - Command: `python -m chandralign.cli register --src <TMC-2 .xml> --ref TCO_MAP_02_N03E021N00E024SC.lbl --out … --matcher sift|eloftr`
  - Both matchers gave **`REJECTED`, failure mode 12, 4 inliers**, `geometry_filter: no DEM`,
    `parallax: off`.
  - The script path on the same products (`register_tmc2_tc.py`, N03 row 18750) gives **HIGH, 0.461 px,
    coverage 1.0, 15,145 inliers**.
- **OHRC → NAC:**
  - The first tiles are **34.7 km apart** and the result is `REJECTED`.
  - The CLI then **crashes** in the exporters with
    `GeolocationUnavailable: M102014464RC: no IMAGE_MAP_PROJECTION`.

**What the scripts do that the product lacks** (the exact list; mirror it):
1. **Footprint overlap and window placement.** Choose a source window inside the reference footprint using
   the source's *system* geolocation:
   - TMC-2: `CornerModel`.
   - OHRC: `load_grid_model`.
   - Reference footprint: TC's `MapModel`; for NAC, the LROC corners in `data/pairs/*_lroc_meta.json`
     (`Nac` / `NacGeo` in `register_tmc2_nac.py`, `register_ohrc_nac.py`).
2. **Prior:** an affine from source-window px to reference px, fitted through an 11×11 grid of system lat/lon
   (`A_sys`, `register_tmc2_tc.py:184-195`), optionally shifted by the geoprior or geodetic bridge.
3. **Coarse lock:** MIND template search over ±7 km (TMC-2) or ±4 km (OHRC), accepted only if z ≥ 10
   (`register_tmc2_tc.py:215-249`, `cascade.register_step_dense`). The system geolocation was **4.85 km**
   off in the audited window.
4. **Resample the source into the reference frame** with `warp_affine(src, Wf)` (anti-aliased), so the
   matcher sees about 1:1 scale.
5. **Matcher from `routing.choose(src_instr, ref_instr)`**, including `choice.candidates()` fallbacks.
6. **Fine-stage inputs:**
   - `ground_model=_OffsetModel(...)`
   - `dem=` an SLDEM2015 patch
   - `parallax_dem=` the TC DTM
   - stage override `{"parallax": True}`

   `register_bundle` has no `parallax_dem`, `parallax_height_at` or `rematch` parameter
   (`pipeline.py:381-383` vs `fine_stage` at `:188-193`).
7. **Expected scale:** `scale.expected_scale(pixel_scale(src), tc_pixel_scale(tc, lat))`.
8. **Compose back to source px:** `T_total = T(o_f) @ R @ Wf`, then `to_source_px` for the RMSE and
   known-shift error.
9. **Export compatibility.** The script planes have `meta=None`, but `provenance.build`
   (`provenance.py:62-63`) and `matchpoints._model_from_plane` (`:153-156`) require meta.

**Fix:**
1. Promote the scripts' `run_window` logic (TMC-2/TC; OHRC/NAC's `run_window`/`_fine`) into a library
   function, e.g. `pipeline.register_products(src_meta, ref_meta, *, matcher=None, windows=…)`. It should
   return a `RegistrationBundle` carrying src/ref meta, **tile origins** and **separate** ground models.
2. Extend `register_bundle` with `parallax_dem`, `parallax_height_at`, `rematch`, `expected_scale` and
   separate `src_ground_model` / `ref_ground_model`.
3. Replace every `"sift"` default with `None`, meaning routing decides.
4. Make the CLI and API call the new function.
5. Implement or remove the `benchmark`, `ablate` and `demo` subcommands, which are `_pending` stubs
   (`cli.py:33-45,107-108`).

**Accept when:**
- Running `chandralign register` on every window of `reports/tmc2_tc_registration.json` and every OHRC → NAC
  protocol window gives the **same tier and RMSE as the script, within 0.05 px, per window**.
- An OHRC → NAC run completes without crashing.
- Add this as a slow real-data test.

### C-02 [B] Sub-pixel refinement in the product path makes the delivered points worse (PREC-01)

**Where:** `refine/subpixel.py:303-306` (`refine_points`), called from `pipeline.py:321`.

**What is wrong:** for each match it cuts an **axis-aligned** patch around the source point in the raw
source image and an axis-aligned patch around the reference point in the raw reference image. It then
estimates a pure translation between them and moves the point by up to `max_move=1.5` px. If the two images
differ in rotation or scale, which they do in the product path, the patches do not contain the same ground
in the same shape, so the translation estimate is biased. The scripts avoid this only because they
pre-resample the source into the reference frame first (`register_tmc2_tc.py:256-258`).

**Evidence** (known-warp harness on real TMC-2 and OHRC crops; the truth is exact; errors in ref px):

| Case | Unrefined p50/p95 | **Shipped refine** p50/p95 | Warped NCC p50/p95 | Warped LSM p50/p95 |
|---|---|---|---|---|
| TMC r60k, small warp, non-rigid | 0.142 / 0.442 | 0.167 / 0.489 | 0.064 / 0.166 | 0.050 / 0.147 |
| OHRC, small warp, non-rigid | 0.086 / 0.242 | 0.160 / 0.358 | 0.045 / 0.110 | 0.030 / 0.071 |
| TMC r60k, LARGE warp (10°, scale 0.6) | 0.190 / 0.487 | 0.236 / **1.293** | 0.057 / 0.136 | 0.044 / 0.115 |
| TMC r110k, LARGE, mild illumination | 0.214 / 0.569 | 0.321 / **1.385** | 0.069 / 0.191 | 0.073 / 0.182 |
| OHRC, LARGE, mild illumination | 0.178 / 0.442 | 0.199 / **1.347** | 0.057 / 0.126 | 0.059 / 0.174 |

- **The shipped refinement is worse than no refinement in 11 of 15 cases.**
- On real OHRC → NAC (`reports/ohrc_nac_registration.json`), refinement **raised** the residual-to-model in
  23 of 47 method-windows.
- PREC-06's own evidence (`scripts/verify_subpixel.py`) is a pure translation of the same image, so it
  cannot see this.

**How the harness was built** (rebuild it if the scratch copy is gone; see §9):
- Take a real crop (TMC-2 rows 60000/110000, block 2; OHRC row 30000, block 4).
- Reference = the crop resampled through a known map G (ref → src): sub-pixel shift (0.37, −0.62) +
  rotation + scale + a smooth non-rigid field (1.2 px amplitude, 300–390 px wavelength).
- Add independent sensor-like noise to each image.
- Truth for any source point = G⁻¹.
- Conditions: small (2.5°, scale 0.93) and large (10°, scale 0.6) warps; radiometry same, "mild" (gamma 0.6
  plus a 0.75–1.25 gain ramp) and "inverted" (a sign-flipped shading proxy for an opposite sun).

**Fix:**
1. Before refining a point, resample the **source patch through the model's local Jacobian** so it lies in
   the reference patch's geometry. Alternatively, run the whole fine stage in a common pre-warped frame, as
   the scripts do.
2. Use **least-squares matching (LSM)**: affine + radiometric gain/offset, e.g. `cv2.findTransformECC` with
   `MOTION_AFFINE` on warped patches, or a Gauss-Newton LSM. Keep NCC-warped as the fallback.
3. **Accept a move only if the match score (NCC/ECC) increases.** Keep `max_move` but cap it lower
   (~0.75 px) once patches are warped.
4. Remove or demote `corner`: it moves ≤2% of points (PREC-03 is a no-op here). Prefer `phase` over
   `phase_iter`, which was worse in every warped case (0.13–0.22 vs 0.09–0.15); `_dense_refine` and the
   cascade use `phase_iter`.

**Accept when:** on the known-warp harness (all conditions, both warp sizes), refined points beat unrefined
in **15/15 cases at both p50 and p95**, with p95 ≤ 0.25 ref px on the non-inverted cases. On the real
OHRC → NAC and TMC-2 → TC windows, the refinement lowers residual-to-model in ≥ 90% of method-windows.

### C-03 [B] The reported RMSE is not an accuracy figure, and it describes a geometry that is not delivered

**Where:**
- `pipeline.py:344` is `_rmse(model, cs, cr)`, where `model` is the **affine** and `cs/cr` are the delivered
  points.
- `product/warp.py:14-21` (`best_geometry`) warps with **TPS or parallax** whenever they exist.
- `evaluate/metrics.py::compute_metrics` (the module OUT-04 names) is imported only by tests.
- `rmse_m` is always null (`pipeline.py:434`).

**What is wrong:**
1. The number shown as "RMSE" in `result.json`, the HTML report and the UI is the **in-sample residual of
   the affine** on its own inliers. Those inliers were pre-screened at 3 px, so the figure is biased low for
   an affine and meaningless for the TPS or parallax model actually delivered.
2. It is not in source px, the problem statement's unit, and `rmse_m` is never filled.
3. Two definitions coexist: the product gives 0.461 px and `metrics.py` gives 0.719 px on the same window.

**Evidence:**

| Case | Reported "RMSE" | True error of the delivered geometry |
|---|---|---|
| Non-rigid harness | 1.14–1.18 px | TPS 0.09–0.14 |
| Rigid harness | 0.19–0.23 px | affine 0.02–0.04 |
| Committed TMC-2 → TC run (`reports/tmc2_tc_registration_height_ref.json`) | 4.12, 6.96, 6.89, 8.77, 6.25, 6.05, 3.71, 4.95, 11.08 px on HIGH/MEDIUM windows | parallax model residual 0.53–0.85 px |

**Fix:**
1. Before fitting, hold out about 20% of inliers stratified by grid cell (or use spatial-block k-fold).
2. Report the **check-point RMSE of the geometry `best_geometry` will use**, as `rmse_px_ref`,
   `rmse_px_src` and `rmse_m`, each tagged with its point set and model.
3. Keep today's figure only as `fit_residual_px`.
4. Remove `metrics.py` or make it the single definition.
5. Set `rmse_px=None` below `min_inliers`. Today a degenerate 4-point fit shows `rmse_px 0.0`.

**Accept when:** on the known-warp harness, the reported check-point RMSE is within 25% of the true
dense-grid error of the delivered geometry in every case. On TMC-2 → TC it agrees with the NCC-probe p50 to
within a factor of 1.5.

### C-04 [B] The only defence against confident wrong answers (`crosscheck_gate`) is never called

**Where:** `evaluate/control_gates.py:262` defines `crosscheck_gate`. Its only caller is
`scripts/rift_crosscheck.py:61`. Neither `pipeline.register_bundle` nor any `register_*.py` script calls it.

**What is wrong:** the project's own measurement (`docs/part2_evidence_summary.md`, 900 runs) shows that when
false matches agree with each other, every robust estimator returns the outliers' transform and a clean fit:
110–114 confident wrong answers per 300 runs. The five shipped gates (blank, noise, perturbation, identity,
shared mask) **pass consistently wrong answers by design**, as the comment at `control_gates.py:269-270`
says. RIFT2 as an independent, differently-failing checker caught **8 of 12** of those
(`reports/rift_crosscheck.json`), against 2/12 for the standard gates.

**Failure scenario:** a real window over repetitive terrain (crater chains, rilles) where the matcher locks
one repeat unit off. MAGSAC accepts the result, every gate passes, and it ships as HIGH.

**Fix:**
1. In `register_bundle`, after the primary match, run a checker from a different family whenever the
   primary matcher is not that family: RIFT2 (`matching/rift.py`, vendored, licence-clear) or the MIND dense
   step.
2. Fold its `GateResult` into `gates` before `quality.assess()`.
3. Put it behind a config flag, default ON.
4. If the checker cannot lock, the result must be **"inconclusive"** (cap the tier), not a pass.

**Accept when:**
- `scripts/rift_crosscheck.py`'s protocol, run end to end through `register_bundle`, catches ≥ 8/12.
- On the committed real windows (TMC-2 → TC 15, OHRC → NAC 25, IIRS → WAC 5) the false-alarm rate is
  measured and reported. Record it in a frozen protocol before running.
- A proper periodic-aliasing trap is built and tested: two different real crops of similarly-spaced
  repetitive terrain, **not** `np.roll` of one crop, which is a true correspondence.

### C-05 [A] The web UI shows fabricated registration results

**Where:** `src/chandralign/ui/app.js:11-59` (hard-coded `PAIRS`), `:68` (`isMock: true` default),
`:465-492`, `:525-589` (`runLive` always posts `mock:true` at `:533`), `:571`
(`res.confidence_tier || "SILVER"`), `:614-631` (fake downloads), `:196-201` (uploads never sent).

**What is wrong:**
- The UI hard-codes tier **"GOLD"**, RMSE **0.78 px**, **512 inliers**, 86.4% ratio and so on, under
  **invented product IDs** (`CH2_OHRC_20200214 ⇄ LRO_NAC_M119283`, `SELENE_TC_MN00001`). Images are a
  procedural canvas, and the match points come from `Math.random()`.
- The tier vocabulary GOLD/SILVER/BRONZE/HARD does not exist in the contract, which is
  `HIGH/MEDIUM/LOW/REJECTED` (`contracts.py:24`). Real HIGH/MEDIUM/LOW have no styling and fall back to a
  "positive" silver badge.
- The rejection codes shown ("#01 FEW_INLIERS", "#12 DELAUNAY_LARGE_GAP") are not in the failure-mode
  register. Real mode 12 is "False correspondences survive robust fitting".
- **Any backend error silently swaps in the fake GOLD result.** The UI's default matcher `auto` is not a
  valid name, so the backend fails, and the UI then shows GOLD.
- This is failure mode #19 in the research doc ("Fabricated/inflated evaluation numbers"), in the one
  surface judges will see.

**Evidence:** Playwright against a live uvicorn. A live run with matcher `auto` logs "Backend error …
falling back to simulation", then displays GOLD / 0.78 px / 512 inliers.

**Fix:**
1. Delete the metric tables in `PAIRS`.
2. Drive the UI from `GET /pairs` plus **real cached runs** (`result.json` and PNG assets produced by C-01 on
   real data, committed or regenerated).
3. Use the real tier vocabulary with distinct styling. LOW must look cautionary and REJECTED must look like
   a refusal.
4. Render failure modes by name and mitigation via `failure_log.modes(...)`.
5. On any error, **show the error**; never fall back to a canned result.
6. Default the matcher to routing (`None`), not `auto`.
7. Let live mode submit real `src`/`ref` labels.

**Accept when:** `grep -n "GOLD\|SILVER\|BRONZE\|0.78\|512" src/chandralign/ui` finds nothing. A headless
run with the backend stopped shows an error state. A live run shows exactly the numbers in that run's
`result.json`.

### C-06 [A] The REST API has a path-traversal hole, and its test suite has never run

**Where:**

- `api.py:373-378,576` (binds `0.0.0.0`, CORS `*`, `reload=True`).

## 4. Important issues

### I-01 [B] TPS always overrides the affine, and is fitted on too few points (ALIGN-02)

`product/warp.py:14-21` (`best_geometry`) always prefers TPS. TPS is fitted on ≤384 thinned points with
cross-validated smoothing chosen from {0.1…1000}. `residual_structure` (`robust.py:261`) is computed but
gates nothing.
- **On rigid pairs TPS is 3–5× worse** than the affine: 0.089–0.119 vs 0.021–0.036 px.
- On non-rigid pairs, TPS is much better than the affine (0.09–0.35 vs 0.71–1.13), and TPS fitted on
  correctly refined points is 2–6× better again (0.02–0.09).
- `scripts/tps_heldout.py`'s "held-out" points are the affine's own fit inliers, so it cannot see the rigid
  regression.

**Fix:** choose the delivered model per registration by **spatial-block cross-validation on all refined
inliers** (affine vs TPS vs parallax). Fit TPS on all inliers with robust IRLS (Huber/Cauchy), and keep the
384 uniform points for export only.
**Accept when:** on the harness, the selected model is never worse than the best single model by more than
10%, and TPS on all LSM-refined inliers reaches 0.02–0.09 px.

### I-02 [B] The estimator's refusal is ignored (ALIGN-01)

`pipeline.py:235-239` checks only `first.model is None`, never `first.ok`. `robust.estimate` returns
`ok=False` below `estimate.min_inliers=12`, but `tiers.low` accepts from 8.
**Demonstrated:** 10 true + 14 random matches gave `first.ok=False` ("… not trustworthy") yet
`fine_stage ok=True` and the tier was **LOW (accepted)**.
**Fix:** `if not first.ok: return FineResult(False, …)`, or align `tiers.low.min_inliers` with
`estimate.min_inliers`.
**Accept when:** that exact case is REJECTED (add it as a test).

### I-03 [A] The scale gate (CHECK-05) never fires in the product

`cli.py:83` and `api.py:225,244` never pass `expected_scale=`, so `pipeline.py:420-423` records
`scale_status="not checked"` with `scale_ok=True` on every product run. Failure mode #13 (locking at the
wrong scale) is therefore unguarded.
**Fix:** part of C-01. Compute `expected_scale` from both products' GSDs, as `register_tmc2_tc.py` does.

### I-04 [A] The NAC pixel size used for routing is always the nominal 0.5 m label value (GEO-06)

`io/instruments.py:177-200` (`_gsd_of`) → `estimate/scale.py:197-241` (`pixel_scale`). NAC labels carry no
corner coordinates, and the footprint-derived GSD is only used when a caller passes `ground_extent_m`, which
`_gsd_of` never does.
**Reproduced:** `scale_precheck(M102014464RC, M109080308LC)` → ratio **1.00**, `source='label'`. The team's
own `scripts/audit_gsd.py` measured about **2.15×** for that pair. Real NAC GSDs range 0.55–1.27 m against
the 0.5 m label. Near the 4× cascade threshold this can flip routing.
**Fix:** pass `Reference.footprint` (already loaded via ODE) into `pixel_scale(meta, ground_extent_m=…)`.
**Accept when:** `scale_precheck` on `audit_gsd.py`'s pairs agrees with its measured ratios.

### I-05 [B] The best dense matchers already installed were never benchmarked

The pinned `vismatch 1.3.2` exposes `roma`, `minima-roma`, `matchanything-roma`, `romav2`, `ufm`, `gim-dkm`
and `tiny-roma`. None is in the default-matcher pool (`docs/default_matcher_protocol.md` §2) or in
`reports/licence_audit.json`. They were never considered, as opposed to measured and rejected. All current
matchers except MIND are LoFTR-family and share failure modes. See G-03 for the plan.

### I-06 [A/B] The licence gate is a denylist, and 4 non-shippable models pass it

**Verified:** `restriction_reason()` returns `None` (meaning shippable) for:

### I-07 [B] OHRC → NAC "20/25 solved" hides 8 MI-flagged windows and 10 unmeasurable ones

`scripts/register_ohrc_nac.py:329,489`: the MI check is computed and then ignored by the success rule, which

### I-09 [B] Routing's fallbacks and classifications are obeyed only by the OHRC → NAC script (MATCH-09)

### I-17 [B] The pipeline never uses ISRO's own refined geolocation as a search prior

`geometry/projection.py:315` (`geolocation_model(prefer="independent")`). No caller in `src/` passes
`prefer="precise"`.
- TMC-2 and IIRS labels carry `Refined_Corner_Coordinates` and a `g_grd` grid, already adjusted by ISRO
  against SELENE (`<isda:reference_data_used>SELENE`).
- Refined minus system is about **5.1 km** for TMC-2 and **13.2 km** for IIRS. That agrees with three
  independent sources (`accuracy.md` check 11; the `geoprior.py` docstring; the measured TMC-2 → TC offset,
  median 4.68 km), so it holds about **85–95%** of the correction.
- `geometry/geoprior.py` is a hand-fitted lookup for **three exact product IDs** and returns zero correction
  for every other product among the >25,000.

**Important nuance:** keeping the refined model out of **evaluation** is correct, because it is SELENE-tuned
and would leak the reference. Using it as the **search prior** is not circular, since the match is then
validated independently.
**Fix:** add a "best prior for search" mode: for any TMC-2/IIRS product with `reference_data_used=SELENE`,
`geoprior.load()` falls back to `read_corner_sets(label)["refined"]` vs `["system"]`
(`io/pds_label.py:206-230`). Keep `prefer="independent"` for grading.
**Accept when:** on a TMC-2/IIRS product **not** already in `geoprior`'s tables, the coarse lock succeeds
with a smaller search radius, and time-to-lock and radius are reported before and after.

## 6. Accuracy upgrades: the road to an "almost perfect" matcher

Ranked by **measured or expected gain**. Every item names its measurement. Freeze each criterion before
running it (§0.4).

### G-01 Geometry-aware LSM refinement (the fix for C-02)
- **Measured:** delivered-point median 0.16–0.32 → **0.03–0.07 px**, p95 up to 1.39 → **≤0.23 px** (up to
  10× at p95). This is the single largest measured gain.
- **Measure:** the known-warp harness (rigid, non-rigid, mild; small and large warp), plus the share of real
  OHRC → NAC and TMC-2 → TC method-windows where refinement lowers the residual (today 24/47).

### G-02 Fit the delivered geometry on all refined inliers; select the model by cross-validation (the fix for I-01 and C-03)
- **Measured:** TPS on all LSM-refined inliers 0.019–0.087 px, against the shipped TPS 0.089–0.345. It never
  loses to the affine on rigid pairs.
- **Measure:** dense-grid error against the known warp; check-point RMSE and NCC-probe p95 on the real
  windows.

### G-03 Benchmark the RoMa family already inside `vismatch 1.3.2`
- **Candidates:**
  - `minima-roma`: MINIMA Apache-2.0 + RoMa MIT + DINOv2 Apache-2.0. Best candidate for the illumination
    and cross-sensor fallback slot.
  - `roma`, `matchanything-roma`: the latter depends on the pin, like eloftr.
  - `ufm`, `gim-dkm`: licence audit needed.
  - `romav2`: benchmark-only; its DINOv3 backbone is not OSI.
  - Keep `master`/`duster` out (CC BY-NC-SA).
- **Why:** RoMa's DINOv2 coarse features are the strongest published signal for large appearance change,
  and its dense warp plus certainty targets the "few, weak correspondences, 2–3 px precision" regime where
  the open cases fail.
- **Partial evidence (1 window, possibly contaminated run; UNVERIFIED):** OHRC → NAC M1417360906LC
  (75° sun), row 48548. Known-shift error: `minima-roma` **0.29 px** vs `minima-loftr` 0.656 px; plain
  `roma` failed at 1259 px. All three were still REJECTED; minima-loftr's cause is the `null_random_noise`
  gate.
- **Before the comparison is fair:** set `max_num_keypoints` ≥ 5000 for dense models (M-06), and make the
  noise null gate use a certainty threshold for dense models (they can fail it structurally). Add allowlist
  rows (I-06).
- **Measure:** each candidate is one argument to the existing scripts:
  - `register_tmc2_tc.py --matcher minima-roma` (vs `reports/tmc2_tc_registration.json`)
  - `register_ohrc_nac.py --auto-bridge --matchers eloftr minima-loftr minima-roma roma`, all 5 NACs
  - `register_iirs_wac.py --matchers xoftr minima-roma matchanything-roma rift2 sift`
  - `register_iirs_nac.py --dense` vs `--matchers minima-roma`
  - `register_to_map.py` for MI/WAC, after adding `--matchers`
  - `sweep_illumination.py` and `bench_rift.py`

  Compare perturbation error, inliers, coverage, MI flags and probe p95 in source px.
- **Budget:** about 20 min per OHRC window with 3 matchers. It stalled at 14.5 GB RAM when other jobs ran,
  so run it on an idle machine.

### G-04 Independent-truth check points for every pairing (the biggest gain in trustworthiness)
- Today **no pairing has a ground-truth check-point set**. Every accuracy number is self-consistency, NCC
  probes or MI, which see the same two images and can share a shading bias with the matcher.
- **Options:**
  - 30–50 points per pairing located by a method that shares nothing with the matcher: LROC NAC DTM or
    orthophoto tie points, or crater centroids fitted separately in each image.
  - For OHRC, NAC-derived orthophotos and DTM-rendered references (LROC NAC DTMs exist near Apollo 11).
- **Measure:** the §7 table, re-computed against these points, p50/p95 in source px.

### G-05 Illumination-invariant refinement and rendered references for opposite and overhead sun
- In the "inverted" proxy every intensity method had nothing to refine.
- LSM or inverse-compositional Lucas-Kanade on **MIND or phase-congruency channels** (the repo already has
  `mind()`).
- For OHRC → NAC, render the reference DTM under OHRC's sun. That addresses the M175 opposed-sun case and the
  ~2 m bias.
- **Measure:** MI flags and probe p95 in OHRC px on M175, M109 and M1417.

### G-06 Dense regularised residual field after the affine + parallax model (the TMC-2 → TC tail)
- Pyramidal DIS or Farnebäck, or RAFT/GMFlow on MIND images, over the overlap; then uniform-by-construction
  control points and a smooth field.
- This targets the TMC-2 → TC p95 of 1.32 src px (hilly N00 windows 1.15–1.87) and gives coverage 1.0
  without refill.
- **Target:** p95 < 1 src px on every window. **Measure:** probe p95 per window.

### G-07 Uniformity inside cells
- Grid top-k, then farthest-point or quality×spacing selection inside each cell.
- Measured on the delivered points: NN-CV 0.73–0.92 today (uniform random ≈ 0.52; FPS 0.13, per
  `usefulness_checks` U2). This is what the problem statement asks for, and it is cheap.
- **Measure:** NN-CV and max Delaunay gap in **both** frames over the valid overlap.

### G-08 ISRO refined geometry as the search prior (I-17)
- This shrinks the coarse search from 5–13 km to about the residual after ISRO's SELENE adjustment.
- **Measure:** radius to first lock and wall time on a held-out product.

### G-09 Reconsider the default matcher with the cross-check live
- In the 720-run protocol `xoftr` was the only eligible candidate (100% core, 0 false confidences) and
  `eloftr` had 1 false confidence in 80. `eloftr` was chosen on a 9-window real test plus a runtime budget
  (xoftr is 5.3× slower).
- Once C-04 is live, re-run the false-confidence column for eloftr vs xoftr vs minima-roma and re-decide the
  speed/safety trade on that number.

### G-10 Rigorous sensor model + DEM bundle adjustment (longer term)
- Pushbroom attitude polynomials or RPC bias compensation, with heights from SLDEM or the TC DTM, solved
  jointly over overlapping windows.
- This generalises ALIGN-08 to OHRC/IIRS and replaces "affine + TPS".
- **Measure:** closure error across windows, the hilly-window probe error, and the offset vs the ISRO
  refined grid (today 239–636 m).

**Low priority (measured as no gain):** swapping the robust estimator (GC-RANSAC, LO-RANSAC, MAGSAC++). All
variants were within 0.001 px here and in `reports/estimator_benchmark.json`. The real risk is a consistent
false majority, which C-04 and G-08 address, not the estimator.

## 8. Definition of done for this work order

A fix is done when **all** of these hold:
1. Its "Accept when" line is met, with the command and the number recorded in the PR.
2. `pytest -q` and `pytest -q -m ""` pass, and `tests/test_api.py` runs rather than skips.
3. `scripts/sabotage.py --target all` catches every sabotage, run in its own worktree. Add a sabotage for
   each new gate or fix (e.g. "refinement ignores the Jacobian", "crosscheck gate always passes", "tile
   origin dropped").
4. Every adopted real-data result still reproduces (`verify_reproduction.py` after the I-15 fix), or the
   change in results is explained and accepted under a frozen protocol.
5. Accuracy is reported as p50/p95 in source px, with the point set and the model named.
6. `FEATURES.csv` statuses are updated to match reality, including NOT-REACHED where appropriate.
